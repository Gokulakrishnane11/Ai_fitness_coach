## Goal
Split the 999-line `transformation_prediction.py` monolith into a modular, testable `transformation_engine/` package (Doc #1's vision), incorporating reviewer feedback: add a validation layer, separate AI behavior from scientific prediction, ban `st.session_state` from the engine, use a shared `PredictionContext`, and keep the parity test permanently.

`app.py` stays untouched via a backward-compatible shim.

## Verified constraints
- **Only `app.py` imports `transformation_prediction`** — 8 symbols: `load_fat_loss_model, predict_fat_loss, predict_muscle_gain, predict_weight_change, predict_recomposition, weeks_to_goal, generate_milestones, show_simulation_page`.
- **All `st.session_state` usage is confined to `show_simulation_page` (lines 699+).** The engine functions (`calculate_weekly_rates`, `run_simulation`) are already pure dict-in/dict-out. This refactor formalizes that boundary.
- Formulas, clamps, caps, the `alpha=0.20` ML blend, and `fitness_intelligence` integration stay **bit-identical** — pure move + extraction, no numeric rewriting.

## Reviewer feedback → concrete changes
1. **`validator.py`** — formalize the inline `max(min(...))` clamps (currently scattered in `calculate_weekly_rates` lines 166–173) into `validate_inputs(profile, goal, calorie_delta, protein_g, adherence_factor)` → returns a clean, clamped dict + raises on impossible combos (negative height, unknown goal). Pure function, no I/O.
2. **`behavior_adjuster.py`** — extract the AI→science separation. Currently `calculate_weekly_rates` calls `prediction_behavior_factor` (from `fitness_intelligence`) and multiplies rates at the very end (lines 382–387). Move that into `apply_behavior_adjustment(rates_dict, intelligence)` so the scientific core (`goal_logic.py`) has zero knowledge of AI. Enforces Doc #1's "AI refines, never replaces."
3. **No global state in engine** — engine functions already take dicts; `show_simulation_page` will build a `PredictionContext` from `st.session_state` at the boundary and pass it down. Engine never imports `streamlit` or touches session state.
4. **`PredictionContext` dataclass** — replaces the 7-arg parameter lists (`profile, goal, calorie_delta, protein_g, adherence_factor, fitness_intelligence, weeks`). One object, easy to construct in tests.
5. **Permanent parity test** — lives in `tests/test_parity_engine.py`, kept as part of the suite (not deleted). Uses pytest.

## File-by-file move plan

**`utils.py`** — verbatim move of lines 11–57, 140–145 (all constants + `_resolve_adherence_config` + `shared_constants`).

**`model_loader.py`** — verbatim move of `UNIFIED_MODELS`, `load_models`, `load_transformation_models`, `load_fat_loss_model`, `_predict_with_model`.

**`feature_processor.py`** — verbatim move of `preprocess_inputs`, `make_feature_row`.

**`context.py`** (new) — `PredictionContext` dataclass: `profile, goal, calorie_delta, protein_g, adherence_factor, fitness_intelligence, weeks`. With a `from_session_state(ss)` classmethod and `from_profile(...)` factory for tests. This is the single object threaded through the engine.

**`validator.py`** (new) — `validate_inputs(ctx_or_dict) -> dict`: formalizes the inline clamps at monolith lines 166–173 (weight 30–250, height 100–250, age 10–100, workout_days 0–7, sleep 0–24, protein ≥0, adherence 0–1). Raises `ValueError` for unknown goals or impossible bodies. Returns a sanitized profile dict.

**`physiology_engine.py`** (new helper) — `calculate_body_metrics(weight, height, age, gender, workout_days, steps, activity_level)` returning `{bmi, bmr, tdee, multiplier, maintenance_calories}`. Removes the duplication between `calculate_weekly_rates` (178–195) and `run_simulation` (547–563).

**`goal_logic.py`** — the 4 goal branches (Fat Loss/Muscle Gain/Weight Gain/Recomp) factored out of `calculate_weekly_rates` into `compute_goal_rates(goal, metrics, scores)`. Pure science: deficit/surplus math, protein adequacy, training volume, recovery, rate caps. **No ML, no AI** — returns raw scientific rates. (The ML `alpha=0.20` blend stays in the orchestrator since it needs `model_loader`.)

**`behavior_adjuster.py`** (new) — `apply_behavior_adjustment(rates, intelligence)`: wraps the `ai_factor` multiplication currently at monolith lines 382–387. Calls `fitness_intelligence.prediction_behavior_factor`. Returns adjusted rates. This is the **single chokepoint** where AI touches science — everything else is AI-free.

**`prediction_engine.py`** — `calculate_weekly_rates(ctx)` orchestrator: validate → physiology → sub-scores → `goal_logic` → ML blend → `behavior_adjuster`. Same return dict as today. Plus verbatim `predict_fat_loss/muscle_gain/weight_change/recomposition` (now accepting either legacy args or a `PredictionContext`), `calculate_metrics`, `predict_static`, `weeks_to_goal`, `generate_milestones`.

**`simulation_engine.py`** — `run_simulation(ctx)` and `simulate_weeks(ctx)` (logic only). The two inlined BMR/TDEE blocks now call `physiology_engine.calculate_body_metrics`. The week-by-week loop, adherence comparison, and chart DataFrames are unchanged.

**`ai_explainer.py`** — `build_goal_insight(goal, cal_delta, protein_g, adherence_label, total_primary, total_muscle, weeks) -> str`. Pure function.

**`simulation_page.py`** — `show_simulation_page(get_profile_fn, require_profile_fn)`: builds a `PredictionContext.from_session_state(st.session_state)` at the top, passes it to `run_simulation`. The insight box calls `ai_explainer.build_goal_insight`. Only module importing `streamlit`.

**`__init__.py`** — re-exports the 8 public names + `PredictionContext`, `calculate_weekly_rates`, `run_simulation`, `load_models`.

**`transformation_prediction.py`** (shim) — ~15 lines re-exporting the 8 names `app.py` imports.

**`tests/test_parity_engine.py`** (permanent) — pytest module. Compares `transformation_engine.calculate_weekly_rates` and `run_simulation` outputs against a frozen baseline fixture (`tests/fixtures/baseline_predictions.json`) across all 4 goals × 5 representative input sets. **How the baseline is captured:** before deleting any old code, I run the *current* `transformation_prediction.py` monolith on the 20 input sets and save outputs as the fixture. The test then guards against any future numeric regression. Also includes the Week-0 parity assertion (Doc #1: `predict_static` == `run_simulation` week 0).

## Implementation order (safe, incremental)
1. **Capture baseline first** — run the existing monolith on 20 input sets (4 goals × 5 profiles), save to `tests/fixtures/baseline_predictions.json`. This locks current behavior before any refactor.
2. Create `utils.py` → `model_loader.py` → `feature_processor.py` → `context.py` → `validator.py` (leaf modules).
3. Add `physiology_engine.py`, `goal_logic.py`, `behavior_adjuster.py`.
4. Add `prediction_engine.py` (orchestrator), `simulation_engine.py`, `ai_explainer.py`, `simulation_page.py`.
5. Add `__init__.py`.
6. Write `tests/test_parity_engine.py` — assert new package matches the captured baseline. Run it. **Must pass before proceeding.**
7. Replace `transformation_prediction.py` with the shim.
8. Re-run parity test + `python -c "import app"` smoke test.
9. Parity test stays in the repo permanently.

## What does NOT change

## Risks & mitigations
- **Formula drift during extraction** → baseline fixture captured *before* any move; permanent parity test enforces it forever after.
- **Circular imports** → strict one-way dependency graph (above); `behavior_adjuster` is a leaf that only imports `fitness_intelligence`.
- **Streamlit import at package load** → only `simulation_page.py` imports streamlit; `import transformation_engine` is streamlit-free and unit-testable.
- **`PredictionContext` migration friction** → wrappers in `prediction_engine.py` accept both legacy positional args and a `PredictionContext`, so internal callers and the shim work without changes.
